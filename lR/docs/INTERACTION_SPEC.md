# M2 — 인터랙션과 상태 계약
[USER_FLOWS](USER_FLOWS.md), [API_CONTRACT](API_CONTRACT.md), [DATA_MODEL](DATA_MODEL.md) 우선. 아래 설계는 API 구현이 아니다.

## 탐색·인증·복귀
공개 홈/검색/상세/기간/견적은 로그인 없이 탐색한다. 거래 생성·찜·수선 접수는 로그인 가드. 로그인 후 productId, channel, 날짜, draft, returnTo를 복원하되 서버 견적·재고를 재조회하고 제출은 자동 재실행하지 않는다. Figma의 로그인 샘플은 렌탈 복귀 경로만 연결; 다른 목적지는 문서상 동작이다.
탭 전환은 각 탭의 탐색 위치를 보존한다. Android 뒤로/상단 뒤로는 시트 닫기→키보드 처리→현재 stack 복귀 순서를 플랫폼 동작과 검증한다. 작성 중 이탈은 OV-05, 결제창 이탈은 상태 조회로 분리한다. 딥링크 민감 내역은 인증·소유권 확인 후 열며 불가 시 일반 오류와 마이 복귀.

## F01 렌탈 — 클릭/서버/상태/복구
| 시작 | 행동 | 조건·서버 처리 | 다음 화면 |
|---|---|---|---|
| HM-01/RT-01 | 상품 선택 | GET products/:id | CM-05 (RENTAL) |
| CM-05 | 기간 선택 | 상품/날짜 context 보존 | RT-02 |
| RT-02 | 시작·반납 선택 | KST [start,return), 시작<반납; 11/10→11/13=3일 | 기간 요약 |
| RT-02 | 확인 | availability 후 quote; 배열 차단일 추정 금지 | RT-03 |
| RT-03 | 예약 진행 | 필요하면 CM-02; 로그인 복귀 시 견적 만료 검사 | RT-04 |
| RT-04 | 동의 후 모의 결제 | POST rentals, 멱등키; 409이면 충돌 분기 | checkoutId·holdExpiresAt 보존 |
| 홀드 존재 | PG 시연/복귀 | confirm 및 status 조회; 클라이언트 redirect로 성공 판정 금지 | EX-02 확인 중 |
| EX-02 | 서버 CONFIRMED | 단 한 번 최종 상태 표시 | RT-05→RT-06 |
| RT-06 | 취소/반납/연장 | 허용 상태·정책 재검증, 취소 확인 | 해당 상세/RT-07/08 |

RT-02: 10일 시작, 11·12일 이용, 13일은 반납 경계로 외곽선/‘반납’ 표시; 13일을 4번째 대여일로 채우지 않는다. 물류 버퍼는 server availability 이유로 안내, 임의 1일 추가 금지. 달력의 ‘불가’는 시작 선택과 반납 경계에 같은 의미를 강제하지 않는다.

RT-03 합성 값: 28,000×3=84,000원, 배송0, 할인0, 보증금100,000원, 지금 결제184,000원. 보증금 선청구는 **policy-demo의 시연**이지 운영정책이 아니다. 정책 미정/가격 누락이면 ‘확인 필요’로 표시하고 실결제 CTA 비활성. 견적은 재고 확보가 아니다.

## F02 구매
SH-01→CM-05에서 구매 선택→SH-02 또는 바로 구매→SH-03. rentals 데이터와 혼합 금지. POST orders에서 재고 홀드와 서버 금액을 확인, 변경되면 차이 표시 후 재동의. confirm/status가 성공한 뒤만 SH-04의 PAID 표시. PAYMENT_PENDING일 때 새 주문 생성 버튼 없음. 실패가 확정되어야 기존 주문에서 안전한 재시도 또는 서버 정책에 따른 새 주문으로 이동한다. 품절은 해당 항목 제거/목록 복귀.
카트는 아직 API가 없으므로 임시 기기 draft 제안이며 재시작/로그인간 병합은 GAP-07 확정 전 약속하지 않는다.

## F03 수선
RP-01→로그인 가드→RP-02. 물품 유형·문제 설명→권한 이유 설명→사용자 선택으로 OS 권한→사진별 업로드→서버 완료 uploadIds만 제출. 다른 사용자의 uploadIds 재사용 금지. 제출 중 버튼 busy, 응답 유실 시 멱등키/내 신청 조회 후 상태 복원. 서버 SUBMITTED 뒤 RP-03에 접수 번호 표시.
QUOTED 전에는 승인/거부 CTA를 숨긴다. 견적 도착 시 금액·버전·범위 확인→수락/거절→POST decision. 견적 변경·409이면 다시 읽고 재동의. APPROVED는 결제 완료와 다르며 실제 과금은 POL-04와 결제 계약 확정 전 활성화하지 않는다.
수선 목록 전용 신규 IA ID를 만들지 않고 MY-01의 수선 내역 섹션에서 RP-03으로 이동한다.

## F04/F05 및 보존
MY-05는 **브랜드→종류→등급·사진·보증서·연락·동의** 3단계. 운영 감정 전 예상가를 확정 지급액으로 표현하지 않는다. POST consignments 성공 후 접수 확인은 화면 내 상태. 조회/재개는 GAP-09.
MY-02 찜은 P1; 실패한 추가/삭제를 조용히 성공 처리하지 않고 원복한다. 원본 ShopLike는 로그인 UI이므로 CM-02로 대응한다. 원본 ShopSell은 MY-05, RecruitApp은 관리자 인력관리 웹으로 유지한다.

| 코드 / 상황 | 고객 문구 | 보존·복구 | 금지 |
|---|---|---|---|
| INVENTORY_CONFLICT | 선택한 기간에 대여할 수 없어요. 다른 기간을 확인해 주세요. | product/날짜 보존, EX-01→RT-02 재조회 | 예약 성공 화면 |
| QUOTE_EXPIRED | 견적 시간이 지났어요. 최신 금액을 확인해 주세요. | RT-03 재견적·변경 재동의 | 오래된 가격으로 결제 |
| HOLD_EXPIRED | 상품 확보 시간이 지났어요. 결제 상태를 확인하고 다시 진행해 주세요. | status 우선; 미승인 확인 뒤 새 견적·홀드 | 결제 진행 중 즉시 새 홀드 |
| PAYMENT_PENDING / timeout | 결제 결과를 확인하고 있어요. 다시 결제하지 않아도 됩니다. | EX-02, status 재조회/내역, 앱 복귀 시 동기화 | timeout=실패 추정 |
| PAYMENT_FAILED | 결제가 완료되지 않았어요. 상태를 확인한 뒤 다시 시도해 주세요. | 서버 실패 확인, 기존 checkout 기준 재시도 | 임의 재주문 |
| UNAUTHENTICATED | 다시 로그인해 주세요. | draft 보존→로그인→서버 재검증 | 결제 자동 실행 |
| FORBIDDEN / 404 | 항목을 확인할 수 없어요. | 목록/마이로 | 타인 데이터·존재 여부 노출 |
| VALIDATION_ERROR | 입력 내용을 확인해 주세요. | 오류 요약+필드별 설명·초점 | 전체 입력 초기화 |
| RATE_LIMITED | 잠시 후 다시 시도해 주세요. | 서버 retry 정보 존중, 상태 알림 | 무한 자동 재시도 |
| SERVER_UNAVAILABLE / offline | 연결을 확인해 주세요. | 읽기 캐시/필터 유지·재시도 | 오프라인 거래 확정 |
| 사진 권한 거부 | 사진을 선택하려면 접근 권한이 필요해요. | 설정 안내/다른 선택 경로/취소 | 즉시 반복 권한 요청 |
| 413 / 422 / 전송 실패 | 사진 크기·형식을 확인해 주세요. / 업로드를 다시 시도해 주세요. | 실패 타일만 교체/재시도, 성공 타일 보존 | 실패 파일 포함 제출 |

## 상태 표시 사전
- Rental: PENDING_PAYMENT 결제 대기; CONFIRMED 예약 확인; PREPARING 준비 중; SHIPPED 배송 중; ACTIVE 이용 중; RETURN_REQUESTED 반납 신청; RETURNED 회수됨; INSPECTING 검수 중; COMPLETED 완료; CANCELED 취소; REFUND_PENDING 환불 처리 중.
- Order: PENDING_PAYMENT 결제 대기; PAID 결제 완료; PROCESSING 준비 중; SHIPPED 배송 중; DELIVERED 배송 완료; PAYMENT_FAILED 결제 실패; CANCELED 취소; REFUND_PENDING 환불 처리 중; REFUNDED 환불 완료.
- Repair: SUBMITTED 접수됨; REVIEWING 확인 중; QUOTED 견적 도착; APPROVED 견적 승인; IN_PROGRESS 수선 중; COMPLETED 완료; REJECTED 거절됨; CANCELLED 취소됨.
배지와 타임라인은 같은 서버 상태에서 파생. 반환품 검수 전에 보증금 환급 완료로 표시하지 않는다.
