# M2 — 반응형·접근성·플랫폼 가이드
2026-11-02에 Exa와 Context7으로 공식 자료 확인. 수치 설계값은 luxuryRental의 제안이며 플랫폼 문서가 모두 같은 수치를 요구한다고 해석하지 않는다.

## 레이아웃
| 조건 | 배치 제안 |
|---|---|
| 360~374 폭 | 좌우16, 상품 2열(짧은 제목), 양식1열; 버튼/텍스트 확대 시 상품1열 |
| 375~430 폭 | 좌우20, 상품2열, 서비스2열, 양식1열 |
| 600 이상 / 회전 | 가용 폭 기준, 내용 최대720 중앙; 상품 최대3열, 거래 폼 최대560; 태블릿 신규 기능 없음 |
| fontScale 1.3 이상 | 상품·서비스1열, 합계 label/value 세로, CTA 높이 자동, 탭 라벨 줄바꿈 허용 |
| fontScale 2.0 / 320 폭 스트레스 | 필수 정보 생략 금지, 전체 스크롤; 달력 대신 시작·반납 입력+기간 확인 대안 |

달력은 가용폭이 348(7×48 + 간격2×6) 미만이면 시작일·반납일 입력형으로 전환한다. 따라서 폭360/좌우16(가용328)에서는 입력형이 기본이다. 큰 글꼴도 같은 대안을 제공한다. 날짜 입력은 별도 레이블·형식 예시·서버 유효성 검사·기간 요약을 갖는다.

폭만으로 기기 종류를 추정하지 않는다. [useWindowDimensions](https://reactnative.dev/docs/usewindowdimensions)는 창 크기와 글꼴 배율 변경을 반영하므로 분할 화면·회전 시 재배치 판단에 사용한다. Figma 390×844는 기준 와이어프레임이며 모든 기기 검수 통과 증거가 아니다.

## 안전영역·키보드·하단 바
[Expo safe areas](https://docs.expo.dev/develop/user-interface/safe-areas/) 및 [system bars](https://docs.expo.dev/develop/user-interface/system-bars/)에 따라 노치·상태바·홈 인디케이터·Android 시스템 바와 콘텐츠가 겹치지 않게 실제 insets를 적용한다.
- 상단 헤더 위 top inset; 좌우 회전 cutout inset; bottom inset 위 CTA/탭. 특정 iPhone의 44/34 같은 값을 운영 상수로 고정하지 않는다.
- 한 경계의 inset 소유자는 1개. navigator가 이미 처리한 여백을 콘텐츠에서 이중 적용하지 않는다.
- 스크롤 본문 끝 여백 = 실제 하단 바 높이 + 겹치지 않게 필요한 추가 간격. 고정 80만으로 모든 기기를 가정하지 않는다.
- 폼 입력을 키보드 위로 스크롤하고 오류 초점을 가리지 않는다. 거래 CTA가 키보드 위에 놓일 때도 마지막 입력과 총액을 읽을 수 있게 한다.
- Android edge-to-edge에서는 시스템 바 배경색 변경만으로 겹침 해결을 시도하지 않는다.
- [Expo Router native tabs](https://docs.expo.dev/router/advanced/native-tabs/)의 자동 insets는 OS/SDK별 차이가 있다. M2는 시각 명세만 정하며 SDK 버전이나 native/custom tabs 패키지를 고정하지 않는다. M4에서 선택한 버전으로 동작을 검증한다.

## 접근성 명세
[React Native Accessibility](https://reactnative.dev/docs/accessibility)에 따라 라벨·역할·선택/비활성/busy 상태를 실제 컨트롤에 제공한다. 하나의 거대 accessible 부모로 독립 액션을 합쳐 숨기지 않는다.

| 항목 | 요구 | 실제 검수 방법 |
|---|---|---|
| 터치 | 전 플랫폼 프로젝트 목표 48×48 논리 단위; M1 44pt 최소 충족 | 보이는 경계+hit area 확인, 인접 영역 겹침 금지 |
| 순서 | 제목→요약→본문→주요 액션→탭 | VoiceOver/TalkBack 스와이프 순서 |
| 입력 오류 | 필드명+오류 원인+수정 방법, 첫 오류로 이동 | 빈 제출/잘못된 날짜/서버422 각각 확인 |
| 모달 | 제목 초점, 배경 비활성, 닫기 후 호출자 복원 | 시트/약관/취소확인에서 초점 탈출 없음 |
| 가격 | ‘일 대여료 28,000원’, ‘보증금 100,000원’ | 거래 유형·단위·합계가 중복/누락 없이 낭독 |
| 달력 | ‘11월13일 반납일, 선택됨’, 불가 이유 | 색 없는 환경, 키보드·스크린리더 선택 대안 |
| 상태 변경 | 결과 수·접수 성공·오류를 적절히 알림 | Android live region, iOS announcement 동작 각각 검증 |
| 큰 글꼴 | 본문/버튼 높이 증가, 약관·금액 축약 없음 | 100/130/200% 및 OS 최대 접근성 크기 |
| 대비 | 본문4.5:1, 큰 글자3:1, 핵심 UI3:1 목표 | 토큰 계산+실제 합성 표면 검수 |
| 이미지 | 상품 설명 alt, 장식은 읽기 제외 | 실패 이미지에서도 상품 식별 가능 |

[AccessibilityInfo](https://reactnative.dev/docs/accessibilityinfo)는 스크린리더·모션 감소 설정과 변경 이벤트를 제공한다. 스크린리더 활성화 전용 기능을 만들지 말고 모든 사용자에게 동일 복구 액션을 제공한다. 모션 감소 시 이동·확대 효과 제거. 홀드 시간 안내는 매초 읽지 않고 임박/만료만 알린다. 서버 만료를 임의 연장하지 않되 재견적·재예약 경로로 복구한다.

## 네이티브 검수 매트릭스 (미실행)
| 환경 | 폭/조건 | 필수 시나리오 |
|---|---|---|
| Android A | 360×800, gesture | 5탭·캘린더·체크아웃·오프라인 |
| Android B | 412×915, 3-button/키보드 | 수선 업로드·로그인·오류 초점 |
| iOS A | 375×812, 노치 | 홈·상품·총액·홈 인디케이터 |
| iOS B | 430×932, 큰 글꼴 | 모든 거래·모달·VoiceOver |
| 추가 | 320 폭, 600/768 폭, 회전·분할, 200% | overflow/기능 누락/중복 여백 |

OS 버전·시뮬레이터/기기명은 실제 실행 시 기록한다. 이 표를 실행 결과로 간주하지 않는다. 핵심 경로의 콘텐츠 겹침·읽기 불가·결제 상태 오인은 출하 차단 결함이다.

## 조사 기록
Context7: /websites/expo_dev(안전영역), /react/react-native-website(접근성) 사용. Exa 검색 1회 5개 결과 중 위 공식 Expo/RN 페이지를 채택하고 다른 라이브러리 결과는 핵심 근거에서 제외했다. 최신 문서의 SDK별 예시가 M1 패키지 버전을 확정하는 것은 아니다. 앱 구현을 시작할 때 선택 버전 문서를 다시 확인한다.
