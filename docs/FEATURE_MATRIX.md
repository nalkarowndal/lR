# M0 FEATURE_MATRIX — 원본 → 신규 모바일 앱 기능 대응표

**As-of:** 2026-11-02 · **Project:** https://github.com/nalkarowndal/lR

## 범례

- **UI**: 화면/사용자 조작 코드가 존재함. 실제 운영 기능이라는 뜻 아님.
- **API**: 저장·조회 코드가 존재함. 보안/운영 QA 완료라는 뜻 아님.
- **DEMO**: 토스트·로컬 상태·모의 결제 등 시연용.
- **STUB**: 비어 있거나 기능 미구현.
- **PROPOSED**: 신규 lR에서 구현할 요구사항.
- **KEEP/ADAPT/REBUILD/SEPARATE**: 새 앱으로 옮기는 방식을 뜻하며, 원본 코드를 지우라는 뜻이 아님.

## 고객용 정보 구조

### 기본안 (디자인 확정 전)
- `Home`: 브랜드 홈, 신규·기획전·추천, 렌탈/구매 경로
- `Rental`: 필터, 목록, 실물 가용성, 예약, 이용 상태
- `Boutique`: 카테고리, 상품 상세, 구매, 주문 상태
- `Care`: 수선·복원 접수 및 조회
- `My`: 계정, 찜, 예약, 주문, 환불/반납, 위탁 신청
- 공통 하위 화면: 통합 검색, 상품 상세, 알림, 로그인·회원가입, 고객센터

**원본 보존 주의:** 기존 하단 탭은 `카테고리/내 상품 판매/홈/좋아요/마이페이지`이며, 신규안 `홈/렌탈/스토어/수선/마이`와 다르다. 실제 전환 전에 화면 명칭·접근 동선·원본을 남기는 방법과 사용자 경험 검수를 문서화한다.

### 관리자/별도 앱
- 기존 `ShopAdmin`의 명품 상품 관리, ERP 입출고/렌탈/주문 운영은 데스크톱 전용 관리자로 설계.
- `RecruitApp`은 **매장 구인·근무자 관리 도구**임. `RecruitApp`을 고객용 채용 공고로 분류하거나 자동 삭제하지 않는다.
- 기존 웹·모바일 사용자의 상품/예약 ID 정책을 합의하여 API 계약에 기록한다.

## 신규 백엔드 API 계약 우선 매핑

| 신규 도메인 | 현재 소스의 기준 | 구현 전 확인 항목 |
|---|---|---|
| `GET /api/v1/products` | 567890 `GET /api/products` | 필드 변환 `title/name, brand, type, price` 및 사진·등급 |
| `GET /api/v1/products/:id/availability` | 1235856894 가용성 조회 | 실제 실물 배정/판매/정비/배송 버퍼 |
| `POST /api/v1/rentals/quote` | 스타터의 서버 가격 계산 | 일수 정의, 배송비, 보증금, 할인/동결 정책 |
| `POST /api/v1/rentals` | 스타터 `POST /api/rentals` | 예약 홀드, 고객 인증, 중복 트랜잭션 |
| `POST /api/v1/orders` | 스타터 `POST /api/orders` | **결제 전 sold 처리 금지**, 재고 홀드 TTL |
| `POST /api/v1/repairs` | 기존 예약된 기획 문서, 현재 빈 `RepairPage` | 사적 사진 업로드, 신청서/상태, 보관 정책 |
| `GET /api/v1/me` | 현재 실제 고객 인증 없음 | 토큰·계정·권한·소유권 |
| `GET /api/v1/admin/...` | 스타터 관리자 `/api/admin/*` | 업무별 RBAC/감사/영속 세션 |

> **모든 `/api/v1` 경로는 신규 앱의 계약 초안이지 구현 완료 엔드포인트가 아니다.**
