# luxuryRental 보안 QA 검증 결과서 (SECURITY_QA)

## 1. 개요
본 문서는 Phase 1(P0 보안 및 개인정보 오류 수정)에 따른 실제 엔드포인트 보안 검증 내역을 기술합니다.

---

## 2. 보안 테스트 케이스 실행 결과

### 2.1 비인증 판매 신청 목록 조회 차단
- **요청**: `GET /api/v1/sell-requests` (헤더 없음)
- **응답 코드**: `401 Unauthorized`
- **응답 본문**: `{"success": false, "error": "로그인이 필요한 서비스입니다."}`
- **결과**: **PASS**

### 2.2 일반 사용자 권한 범위 검증
- **요청**: `GET /api/v1/sell-requests` (USER 권한 토큰)
- **결과**: 본인(`user_id`)이 신청한 건만 반환되며, 타인의 이름, 연락처 등 개인정보는 일체 노출되지 않음.
- **결과**: **PASS**

### 2.3 관리자 전용 엔드포인트 분리
- **요청**: `GET /api/v1/admin/sell-requests` (USER 권한 토큰)
- **응답 코드**: `403 Forbidden` (`{"success": false, "error": "관리자 권한이 필요합니다."}`)
- **요청**: `GET /api/v1/admin/sell-requests` (ADMIN 권한 토큰)
- **응답 코드**: `200 OK`, 전체 위탁 판매 건수 및 관리 데이터 반환.
- **결과**: **PASS**

### 2.4 동명이인 간 데이터 격리 (IDOR 방어)
- **테스트 시나리오**:
  1. 사용자 A('김명품')가 위탁 판매 1건 신청.
  2. 동일한 이름('김명품')을 가진 신규 사용자 B 등록 및 세션 생성.
  3. 사용자 B가 `/api/v1/users/me/sell-requests` 조회.
- **결과**: 사용자 B의 조회 결과 목록 크기 `0` (사용자 A의 신청 건이 노출되지 않음).
- **결과**: **PASS**

### 2.5 프로필 아바타 매직 바이트 검증
- **유효 파일**: Base64 JPEG 전송 시 200 OK 및 `/assets/uploads/avatars/avatar_...` 저장.
- **비정상 파일**: 임의 텍스트 Base64 전송 시 400 Bad Request (`지원되지 않는 이미지 형식입니다.`).
- **결과**: **PASS**
